## Neutral model review gate

Review the render itself, not only screenshots of node graphs, object counts or code. A technical pass cannot override a failed visible likeness.

- [ ] Show a full-body render including shoes; head is not disproportionately large.
- [ ] Show front, both three-quarter views, both profiles, rear three-quarter and direct rear.
- [ ] Show +30° and -30° elevated views with consistent framing.
- [ ] Repeat the facial views using a uniform clay material, without color textures or hair-color tricks obscuring shape.
- [ ] Front view reads as the same person: brow, almond eye aperture, projecting nose, lip proportions, jaw taper and facial-hair arrangement agree with primary references.
- [ ] Profiles have a coherent forehead/nose/lip/chin sequence and jaw-to-neck transition. No broad front face attached to an unrelated back head.
- [ ] Both ears are real modeled geometry with a coherent attachment, interior folds and no duplicated photograph details.
- [ ] Eyelids follow the globes with a continuous margin; no visible white wedges or exposed upper iris band in neutral.
- [ ] Hairline is coherent around temples, ears, crown and nape; asymmetric wavy clumps produce a readable silhouette without a helmet.
- [ ] Lips have volume, a plausible commissure and clear upper/lower separation; the closed neutral mouth is not a hole.
- [ ] Shirt collar, sleeve roll, cuffs/placket, trouser waistband/crotch and shoes hold up in side/back views.
- [ ] No stretched projected face, rear facial features, baked backdrop, black eye sockets or visible UV seams.
- [ ] Triangle counts and topology are measured. Eye/mouth loops and deformation areas are inspected in wireframe; naming alone does not prove suitability.
- [ ] Source `.blend` and reproducible build scripts correspond to the exact reviewed render.

A turntable plus matching clay renders is necessary before declaring Phase 1 accepted. The reviewer must identify unresolved differences explicitly. Use **pass / revise / blocked by missing evidence**, never invented likeness percentages.

## Later gates the neutral render cannot prove

- Eyes: inspect closed/half blinks at gaze extremes and combined smile/blink. An unrigged neutral render cannot establish that clipping never occurs.
- Lips: test lip seal, teeth/lip intersections, FF lower-lip contact, round O/U and open aa, not merely count 15 names.
- Rig: inspect both sides at the required yaw/pitch/roll and shoulders/elbows/wrists/fingers throughout range.
- Expression: large laugh must visibly involve cheeks, eyelids, head and shoulders. Similar shapes under different names do not satisfy emotional range.
- Runtime: inspect a timed two-minute recording with state transitions, real DOM pointing, navigation and interruption. Procedural code does not itself prove natural motion.
- Voice: a system/default voice is a temporary stand-in, not the user's cloned voice. ChatGPT subscription entitlement must be verified through an actually supported integration before promising visitors free API usage.
- Performance: file budgets, frame rate and response latency need actual measurements on named devices and networks.

#### Why the present fitting code misses the identity

1. **The silhouette is barely affected by the fit.** Deformation is permitted only at Y < -0.065, and fades by `(-Y - .065) / .045`. Current cheek contour rays 234/454 hit Y = -0.0776/-0.0755, so only 28%/23% of the requested correction survives. The algorithm disproportionately changes central features while leaving the generic cheek/jaw width. Some jaw contour rays 172/397 miss completely in the current mesh. The code silently drops misses, so it cannot guarantee jaw matching.
2. **Raycasting the old image coordinate is not a persistent anatomical correspondence.** Once the mesh moves, a point may hit a different part of the face or miss. Save explicit mesh-vertex or triangle/barycentric correspondences for anatomical points, and handle silhouette constraints separately.
3. **Pseudo-depth is being used as anatomy.** The code rotates and averages MediaPipe normalized landmarks, including Z, from different photos. Its resulting canonical chin depth is 0.128 for ref27, 0.178 for ref24, 0.289 for ref25 and 0.318 for ref26. That large view-dependent spread is evidence that this is not a measured common 3D surface. Multiplying it by 0.6 does not calibrate it. Profile depth must come from a shared geometry/per-view camera fit or direct profile constraints.
4. **Measurements are stale relative to the render.** The landmark file read during this review was timestamped 03:19, while the latest render was 03:40. The controls describe a previous shape. Every accepted iteration needs source/render/measurement correspondence and a before/after residual report. Reusing the same displacement file on a regenerated starting body is not an iterative converged fit.
5. **Global macro choices and local fit are entangled.** The script first applies generic head, chin, nose, lip and eye morph weights, then a landmark displacement, then hardcoded lip geometry edits. Changes in one stage invalidate assumptions in the next. Expose a small coherent parameter set or use stable region constraints, and evaluate the final surface after all stages.
6. **Depth-gated 2D RBF is not a full head fit.** Its kernel uses X/Z only with a fixed 25 mm radius; it cannot distinguish nearby anatomical surfaces by geodesic location or impose a coherent side-head/jaw profile. Smooth deformation should act on a 3D cage or named regions and include the actual jaw side surface.
7. **Eye construction remains disconnected from eye anatomy.** Iris/pupil disks are placed from averaged joint centers and hardcoded depths. They must be fitted to the globe surface and oriented consistently, then bounded by actual upper/lower lids. Better scalar eye measurements alone will not remove the artificial gaze.
8. **Camera mismatch is unaccounted for.** Orthographic render measurements are compared to close selfie and angled perspective photos. A fitting method can chase perspective distortion as anatomy unless it solves each reference's camera separately.

#### Recommended free path from here

Keep MPFB only as the topology/body starting point. Freeze the current asset as a rejected foundation, and make a **head-only clay fitting iteration** with no hair/beard/material distractions:

1. Establish stable anatomical correspondences on the neutral cage, checking each with a marker render. Add jaw silhouette and profile landmarks explicitly.
2. Use refs 27/24 for front proportions and 14/25/26 for profile depth. Fit one shared head shape but independent perspective camera pose/scale/focal assumptions per image. Do not average monocular Z. Account for expression rather than forcing smiling references into a closed-mouth neutral.
3. Optimize a small set of meaningful Blender/MPFB shape parameters plus smooth region offsets against 2D projected landmarks and manually checked silhouette constraints. Penalize excessive changes and asymmetry. A local SciPy solver can drive numerical fitting without a paid service; render comparisons remain the acceptance authority.
4. Re-render front, camera-matched three-quarter and both profiles; refresh measurements from those exact outputs. Keep camera and geometry changes separate in the report.
5. Once the clay likeness reads correctly, author hair and facial hair to the reference, then return to eyes/material finish. Do not compensate for a generic head using texture, hair or facial hair.

This approach is more defensible than another stock-hair substitution or unconstrained RBF pass. It does not guarantee exact reconstruction from the supplied mixed photographs. The present model remains an unapproved foundation.

### Scalp groom diagnosis and independent authored-guide study

The v8 vertical wall and horizontal shelf were consequences of guide construction, not insufficient strand count. Roots were admitted on the forehead independently of the intended hair-region predicate; every path advanced backward (+Y), then received the scalp's Z at that location. This forced roots up the steep forehead and tips back onto the skull, preventing free curls. Fractional-power envelopes `sin(pi*t)**.8` and `**.65` have unbounded endpoint derivatives; the hard maximum Z then flattened the crests. The front bundles also concentrated hundreds of roots into a nearly single-point footprint. A tangent cross-product against near-parallel global Z made frames unstable on steep portions. More density would reinforce these defects.

Recommended and tested: root patches behind the frontal edge; finite endpoint tangents; explicit independent guide waypoints; parallel-transport frames; normal-based collision clearance instead of projecting every point vertically to the scalp; varied tip lengths; and shorter/interleaved paths below the outermost silhouette. The runtime engineer incorporated the main diagnostic fixes in later versions and excluded actual Ears-mask faces from the substrate.

An independent implementation is saved at `scripts/avatar/study-authored-guide-groom.py`, with sparse and dense front/30-degree/profile evidence in `facebuilder-study/authored-guide-groom/`. It preserves only the v9 substrate and three-point short undercoat, adds nine explicit guide families with finite Hermite tangents and transported frames, then distributes about 10,700 fine fibers across root footprints and depths. It does not change the fitted head, facial shapes, source photographs or the runtime engineer's script.

**Reject the independent first dense pass as final hair.** It removes the vertical curtain, excessive central peak and uncontrolled height, but the front still reads as several similarly rolled tufts above a smooth exposed substrate band. The mesh hairline also has visible stair-step edges. A successful technical curve construction does not establish the reference hairstyle. Removing the upward-turning final controls, making lengths and widths less uniform and covering the front substrate with shorter irregular paths would be necessary before adopting it.

Directly reviewed runtime engineer's `refined-v15-000/030/090.png` against the independent dense pass. **V15 is the stronger next working base**, with more continuous frontal coverage, asymmetric overlap and restrained profile height.
